## Cinnamon scaling follow-up

2026-11-10, m74 (`mint-builder`, 192.168.68.74), native Cinnamon **X11**, under desktop lease `codex-cinnamon-scaling-1376` (18:10:03–18:13:02 UTC). Mint 22.3, Cinnamon 6.6.9+zena, Muffin 6.6.3+zena, cinnamon-settings-daemon 6.6.4+zena, Firefox 158.0+linuxmint1. Tools checkout fetched and detached at origin/nightly `7e6b69b77608f5dc883d38c46382bfb0ac50712c`. Standalone scripts only; no put.gd build installed, built or run. No VM booted.

**Why the earlier 200% attempt failed.** Reproduced: `gsettings set org.cinnamon.desktop.interface scaling-factor 2` alone leaves Muffin's logical-monitor scale and `legacy-ui-scaling-factor` at 1, GTK3 `get_scale_factor()` at 1 and Firefox `devicePixelRatio` at 1 (Xft.dpi=96). The key exists and triggers a settings refresh, but csd-xsettings-manager's `get_window_scale()` obtains the effective integer scale from Muffin `GetCurrentState`'s `legacy-ui-scaling-factor`, rather than taking this key's value. See [the matching settings-daemon 6.6.4 source](https://github.com/linuxmint/cinnamon-settings-daemon/blob/6.6.4/plugins/xsettings/csd-xsettings-manager.c#L577).

**Correct route.** Cinnamon System Settings → Display → Layout → monitor scale 200% → Apply uses Muffin's monitor configuration. The probe drove the same display backend directly: `org.cinnamon.Muffin.DisplayConfig.ApplyMonitorsConfig`, current serial, method **1 (temporary)**, HDMI-1's current 1920x1080@60 mode and logical monitor scale **2.0**. It immediately reported monitor scale=2 and legacy UI scale=2; Firefox DPR=2; the GTK3 witness reported scale=2 and its 500×250 logical client occupied 1000×500 root pixels. Neither a session restart nor an Xft override was needed. These temporary API changes did not write monitors.xml; normal persistent method 2 is documented by [Muffin's display API](https://github.com/linuxmint/muffin/blob/6.6.3/src/org.cinnamon.Muffin.DisplayConfig.xml). Persistent save/confirmation through the settings UI was not exercised.

**Fractional route.** Display → Settings → “Enable fractional scaling controls (experimental)” enables both `scale-monitor-framebuffer` and `x11-randr-fractional-scaling`. `cinnamon_scale.py fractional` performs exactly that installed cs_display.py switch's GSettings operation, preserving any other feature flags. Kept the existing “Scale content down” (`scale-ui-down`) mode and applied monitor scale 1.5 through the same backend. This is the UI-equivalent configuration path, not a simulated click walkthrough. Muffin reported layout-mode=3, x11-fractional-scaling=true, monitor scale=1.5 and legacy UI scale=2. Firefox stayed DPR=2 and GTK stayed scale=2. RandR root framebuffer became **2560×1440**, while the physical output mode stayed **1920×1080**, with a **1.333328** transform and bilinear filter.

Capture: `ximagesrc show-pointer=false use-damage=false startx=0 starty=150 endx=1799 endy=749`, RGB appsink. The probe uses XTest pointer motion and a single button-5 wheel press/release, waits two seconds, and compares every RGB byte of `before[270:]` against `after[:-270]`, including numbered text and barcode boundaries; no masking or resampling. Best non-adjacent candidates have nonzero difference. The 2×2 damage marker lies outside the rectangle. Pointer position is restored after each probe. Firefox kiosk and the GTK witness are isolated windows opened for this run.

**Fractional frames are the unscaled, larger framebuffer**, not the final resampled scanout: ximagesrc returns the requested root-pixel rectangle unchanged, the CSS rows remain 80 framebuffer pixels high, and Firefox's 135-CSS-pixel scroll advances 270 captured pixels. On the physical output those correspond to 60-pixel rows and 202.5-pixel movement. Thus an app logical rectangle 900×300 has 1800×600 source pixels at both these settings; at 150% it spans approximately 1350×450 scanout pixels. A root rectangle is not a post-transform display-pixel rectangle. This measurement supports exact matching on this ximagesrc source; it does not establish byte identity for a post-downsample source or every application.
