## Findings and limits

- **d69 frames/control loop:** the helper log contains 18 terminal runs, 95 `scroll fresh frame` events, and five lost-track terminations explicitly naming a quiet frame stream. Fresh-frame events are recovery attempts, not 95 distinct failed runs. A 24,000 px native Qt page returned `end_of_content` after only 1140 px (`qt-cap-long`); that retained prefix decoded exactly. This is a false-bottom/control-loop/frame-freshness failure, not a demonstrated wrong stitch. That attempt used the initial, slower fixture painter, which repainted the whole document; later fixture revisions paint only the exposed range. A later large-page attempt returned `lost_track` at 870 px. Native-fullsize Qt/GTK also have exact successful runs, so the earlier absolute “no native full-screen frames” symptom is not universal. No baseline comparison establishes whether this predates the PR.
- **GNOME UI / harness:** persistent put.gd notifications overlapped the original y=100 crop. PNG failures show the notification's shadow at the top; the saved during-capture frames show the bar below the region and the ring outside. They do not establish a control-bar leak. y=200 clean runs pass. The orange Shell sharing indicator is already present from the VNC wall; this campaign cannot attribute a baseline indicator change to the scroll session. Pointer stays parked in/near the selection after Wayland captures; X11 restores it. No surprising off-output pointer movement observed.
- **Firefox:** black or partial outputs remain unresolved at the browser-startup/frame-source boundary. They cannot be counted as browser acceptance or confidently called stitcher failures. Chromium was absent on all three hosts.
- **Harness failures retained:** initial CLI history limit 1000 exceeded the API maximum 200; first revision used the wrong settings revision field; browser option parsing was corrected. GNOME `ready` may precede shell bar-placement completion (`scroll_busy`); driver now waits before Start. Activities overview invalidated the first post-login runs. A GNOME retry batch was accidentally started before the preceding batch exited; overlap and `scroll_active` attempts are retained and excluded from acceptance (all `clean` names and the overlapping `quiet` tail). Subsequent y200 runs were serialized. Notifications were disabled only in the private pixel-test profile and restored afterwards.
- **Verifier:** Python/Pillow scanline and barcode-interior verification is intentionally stricter than a row-centre check at integer scale. Text labels, scrollbar and cell boundaries are excluded; saved visuals remain necessary there. GNOME 125% initially failed the integer-style floor mapping because Qt rounds scaled line boundaries. The separate fractional verifier checks each row centre plus every physical barcode scanline within one physical pixel, and passes. d69 fractional remains incomplete regardless of that tolerance.
- **Fixture scope:** the native Python Qt/GTK fixtures paint the test tree's ScrollRuler line patterns without compiling a product or test executable. The browser canvas fixture paints the same patterns. This is not execution of the C++ `test_scroll_page_fixture` binary. The shared one-file driver is `scripts/scroll_run.py`; it supports the original probe HTML as well as fixture-format pixels and preserves operation IDs/RPC transcripts. It was written before package testing and within the first 30 minutes. It needs an already-running isolated resident and a held desktop lease.
- **Memory:** these are bounded settled 30-second samples, not the full 300-second release performance gate. f44's own UI was stopped by verified exact PID before the sample; d69's own UI was closed through an exact-PID KWin script. No pattern kills were used.
