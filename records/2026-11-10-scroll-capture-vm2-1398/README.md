Harness and attribution limits:

- Omarchy's first private runtime hid its Hyprland IPC socket. Those unavailable attempts were preserved; the corrected private runtime linked the real compositor socket and checked both resolved socket lengths before launch. Later text/browser counts use `*verified*` runs after visible right-click dismissal of the old popup. Earlier Omarchy batches remain as diagnostics. The `longclean*` and halfway Omarchy runs predate that dismissal and contain the popup; they do not isolate a core matcher defect.
- Neon Firefox's welcome dialog and Kubuntu Snap's inaccessible `/tmp` profile invalidated their original browser attempts. The dialog was dismissed visibly; Kubuntu used a guest-home profile. Three corrected browser runs were then performed. Budgie's original painted browser runs are valid and are included (5/6 exact total). A retry-script folder prefix `harness-welcome` does not by itself establish invalidity on Budgie.
- The first Omarchy fractional command returned the text “keyword can't work with non-legacy parsers. Use eval.” despite exit 0. That original `fraction` run is **not fractional evidence**. Fresh `og` used `hl.monitor(...)` through `hyprctl eval`, asserted `monitors[0].scale == 1.25`, then restored and asserted scale 1. Its dimensions and all 60 row centres pass, but 165 fine barcode scanlines differ from the strict reference; browser canvas/compositor interpolation versus capture is unresolved, so no exact-raster pass is claimed.
- A first fractional verifier assumed 800 px width and threw on the invalid 100% Omarchy image. The failed verifier log is retained; the corrected verifier rejects dimension mismatch explicitly. No product code or performance harness was changed.
- Height-cap warning visuals use a separate local route so the upload-complete toast does not obscure the warning. The Omarchy maximized-window visual crop was horizontally offset; that raster is excluded from exactness claims. The warning text and its subsequent persistence are visibly established. The full-screen post-notification ruler raster is separately exact.
- The Arch main executable loaded in early manual checks, but the normal installed CLI did not. Both PR and published-nightly normal installs fail on `libcrypto.so.4`; the CLI evidence supersedes any package-wide inference from the main executable alone. The neon native DEB's missing selector is a package/profile limitation; no baseline establishes it as a new regression.

Synthetic uploads used only guest-loopback HTTP receivers on 127.0.0.1:19398 (19399 for native trials), anonymous custom uploader profiles, and generated images/text. No credentials were read or configured, and no real bucket or user object was touched. Receiver-body hashes were matched to PNG hashes and retained archives. Raw multipart bodies, duplicate export archives, global RPC transcripts and private lab keys remain in the private work archives; public evidence contains the PNGs, per-case results/helper logs, MCP events, receipt hashes, identities, decisive visuals and guarded retirement receipts.
