## Failures and baseline comparisons

1. **Hyprland ordinary region after reload (row 5).** Run `hyprctl reload`, press the configured region hotkey, allow the selector to appear, then drag (300,300) to (600,500). Repeat after a second reload. The shortcut creates an operation, but it terminates `failed` / `capture_geometry` instead of producing the selected image. H5 reproduced each failure once; H6 reproduced again while explicitly waiting for the selector layer. [H6 rows](guests/h6/acceptance/rows.jsonl), its `5-reload-*` frames/layer lists and [H5](guests/h5/acceptance) retain each attempt. The exact candidate A on the same two-head desktop also fails twice after each reload ([HA1](guests/ha1/acceptance)); therefore this predates B. PR1481 owns the shortcut/pump coverage being exercised; the observed code points to the existing Hyprland selection/geometry path (PR1471/issue1487 area), rather than demonstrating lost registration from PR1481. Expected: a completed region image after each reload. No catcher remains in the layers lists. No issue was filed or changed.

2. **Known early drag (row 5, issue1487).** In H5 only, begin dragging at the hotkey before the selector appears. The single requested B sample fails `capture_geometry`, the same failure recorded in round A. [Both-head frames and operation](guests/h5/acceptance) are named `5-known-1487-once-*`. [The accepted A record](https://github.com/patrick-hudson/put.gd-evidence/tree/6e4d972354d4526173f0fdb2ae5f3fe5cd79b17a/records/2026-11-13-sweep-a-acceptance) includes A and published nightly 26.1113.4757 failures on the same desktop. Expected: a completed selected image. This is the existing PR1471/1487 behavior, not a new PR1481/1482 finding. No further investigation or work on 1487 was done.

3. **X11 Escape during ordinary recording (row 9).** Start a monitor recording, hide the bar, focus the independent GTK test window, press Escape, then inspect. State remains `recording`, with no error code; it does not stop/review. Explicit pause/resume/Stop still succeeds, exports and plays. B9/B11/B12 reproduce this; [canonical B12](m74/sbm12/physical.json) and [session calls](m74/sbm12/session.jsonl) retain the after-Escape state. [A2 on m74](m74/sba2/physical.json) behaves the same. Expected by this checklist: Escape stops the recording. This is PR1482's XInput/Escape coverage, but the behavior predates B; the current ordinary-recording design uses the recording hotkey/Stop, while the changed Escape watch serves scroll capture. Selection Escape and click highlighting both pass. Frames before/after the step and the exported clip are retained in those runs.

## Harness attempts retained

The record preserves earlier failed attempts, not just successful reruns. Their machine-readable `passed:false` fields must be read with their `driverError` and the canonical run mapping above. These were driver corrections, not candidate fixes: a GDK4 clipboard call unavailable in that API was replaced with its native content provider; tiled fixture clipping/focus was corrected with GTK fullscreen and the existing wlr activation helper (Hyprland 0.56 rejects the legacy dispatch syntax); recording `monitor` without an identity chose PRIMARY rather than the fixture's monitor, so the corrected call explicitly selects `Virtual-N`; retry exports use unique paths to avoid `local_exists`; the lock daemon's inherited SSH stdio was redirected; playback uses the available GTK3/GStreamer player; and P3 waits for/raises a ready editor before proving its exclusion. An oracle obscured by the cursor was corrected by parking the pointer outside it. Early m74 preflight guard failures due to an owned startup notification were retained and resolved by dismissing that notification; the guard threshold was not weakened.

All scripts used for the final runs and their wrappers are in [scripts](scripts) and per-run `acceptance` directories; earlier logs and corrected commands remain. Several initial trials ended before acceptance began. B4's lock-driver timeout was followed by B5's actual visible lock/unlock check. H5/H6 clipboard-driver failures were followed by H7's native-focus clipboard check. The deliberate early-drag test was not repeated by these supplemental runs. The workstation's temporary scratch vanished during an interruption; builder-side evidence survived and was recovered into this permanent record.
